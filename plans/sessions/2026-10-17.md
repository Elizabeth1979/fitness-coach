**Later — Elli: "some buttons trigger other buttons", "couldn't pause", "Change warm-up happens behind the modal".**
Measured in a phone-sized browser before fixing anything:
- The Change sheet itself was stable (no option moves another), so that wasn't it.
- **Double-tap across a screen change was:** a second tap ~120ms later landed on the next screen's button in the
  same spot. Double-tap Start → **Skip** (intro skipped); double-tap ✕ End → **Start** (a new workout began).
  Fix: `ui/useTapGuard` — each screen and sheet drops taps in its first 400ms (keyboard unaffected).
- **Pause:** the engine paused, but speech is queued, so the coach kept talking (worst on the long intro line).
  Pause/Skip/End now cancel speech; Skip cancels before the next line so it isn't delayed.
- **New warm-up / New moves** moved out of the sheet onto Home, as "New" buttons next to the warm-up and the
  circuit they change. The sheet is now settings only.
- With the shorter sheet, the voice picker appearing late would have shifted every button up: it's now there
  (disabled, "Default") from the start. Re-measured: 0 controls move, including when the voices arrive.
- Tests: App-level button tests (New warm-up/moves, each sheet choice selects only itself, Start/Pause/Resume/
  Skip/End, a double-tap doesn't reach the next screen — confirmed failing without the guard), hook test (Pause/
  Skip/unmount silence the coach), guard unit tests. 227 tests, lint, build, browser flow + CSP all green.

**Then — Elli: "Is the speech paused on Pause / leaving the page? Back takes me out of the app."**
- Speech: already fixed in #26 (live since 08:16): Pause and leaving the app (which pauses) cancel the voice.
- Back: `ui/useBackButton` keeps one extra history entry while a sheet is open or you're off Home. Back closes
  the sheet / pauses the workout and goes Home ("Resume where you stopped") / leaves Done for Home. Closing with
  the app's own buttons pops the entry, so Back on Home still exits. Browser-checked all four cases.
- Found on the way (by the new test): `RafClock`'s first frame can be stamped before `start()`, giving a negative
  time; pausing then saved a negative position, which the saved-data check rightly rejects, so Resume vanished.
  dt is now clamped at ≥ 0 (+ test). 231 tests, lint, build, browser flow/CSP/double-tap all green.
